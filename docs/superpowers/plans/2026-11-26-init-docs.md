# `init-docs` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An `npx`-runnable CLI (`ai-skills`) whose first operation, `init-docs`, copies product-agnostic doc templates into a project and maintains a marked documentation block in its `CLAUDE.md`.

**Architecture:** `bin/ai-skills.mjs` discovers operations in `src/operations/` and dispatches by name. Two shared helpers in `src/lib/` do the work: one copies a mirrored template tree (skipping existing files), one inserts or replaces a marked block in a file. Templates live under `templates/<operation>/`, resolved relative to the package, never the working directory.

**Tech Stack:** Node ≥ 20, ES modules (`.mjs`), no runtime dependencies, `vitest` for tests.

**Spec:** `docs/superpowers/specs/2026-11-26-init-docs-design.md`

## Global Constraints

- Plain Node, `.mjs` files only, no runtime dependencies; only `node:` built-ins.
- `vitest` is a devDependency, installed before any other work.
- Package name `@hexmode/ai-skills`; binary `ai-skills`; `engines.node: ">=20"`.
- Markers: `<!-- @hexmode/ai-skills:start -->` and `<!-- @hexmode/ai-skills:end -->`.
- Every doc template's first line is `# <Title>`, third line is `> Status: **Draft**`; no product names.
- Keep ID schemes `REQ-<AREA>-NNN` / `AC-<AREA>-NNN.N`, `D-x.y`, `NF-x.y`, `A-x.y` and the _(My call.)_ convention.
- Existing files under `docs/` are never overwritten.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **`npx` runs from the user's project, not the package.** Templates must resolve via `import.meta.url`; the CLI test runs with `cwd` set to a temp dir (Task 4).
2. **`CLAUDE.md` with CRLF line endings.** Text outside the block is preserved byte for byte when the block is replaced (Task 2).
3. **Empty or whitespace-only `CLAUDE.md`.** Result is exactly the block plus `\n`, with no leading blank lines (Task 2).
4. **A project that already has some docs.** A pre-existing `docs/product/vision.md` with user content stays untouched while the others are created (Task 3).
5. **`.gitkeep` survives packaging.** `npm pack --dry-run` lists `templates/init-docs/files/docs/requirements/.gitkeep` (Task 4).

### Task 2: `upsertManagedBlock`

**Files:**
- Create: `src/lib/managed-block.mjs`
- Test: `test/lib/managed-block.test.mjs`

**Interfaces:**
- Produces:
  - `markersFor(name: string): { start: string, end: string }` returns `<!-- ${name}:start -->` and `<!-- ${name}:end -->`.
  - `upsertManagedBlock(filePath: string, content: string, markers: { start, end }): Promise<'created' | 'updated' | 'unchanged'>`.
  - The block text is `${start}\n\n${content.trim()}\n\n${end}`.

- [ ] **Step 1: Write the failing tests** (markers come from `markersFor('@hexmode/ai-skills')`; `B` is the block text for content `hello`)

- `markersFor builds HTML comment markers`: the result equals the two Global Constraints marker strings.
- `creates the file when missing`: returns `'created'`, and the file equals `B + '\n'`.
- `treats an empty or whitespace-only file as empty`: the file contains `'  \n\n'`, the call returns `'updated'`, and the file equals `B + '\n'`.
- `appends to a file without a block`: `'# Title\nText\n'` becomes `'# Title\nText\n\n' + B + '\n'`, and the call returns `'updated'`.
- `replaces an existing block and keeps the rest`: `'head\n' + oldBlock + '\ntail\n'` becomes `'head\n' + B + '\ntail\n'`.
- `preserves CRLF text outside the block`: `'a\r\nb\r\n' + oldBlock + '\r\nc\r\n'` keeps `'a\r\nb\r\n'` and `'\r\nc\r\n'` unchanged around `B`.
- `returns unchanged and does not write when identical`: the file already holds `B`. The call returns `'unchanged'` and the file's `mtimeMs` doesn't change (set the mtime to the past with `fs.utimes` first).
- `rejects malformed markers and leaves the file untouched`: three cases (start only, end only, two blocks) each reject with an error whose message contains the file path and `marker`, and the file contents stay the same.

- [ ] **Step 2: Run the tests to verify they fail**

Run: `npx vitest run test/lib/managed-block.test.mjs`
Expected: FAIL, because the module isn't found.

- [ ] **Step 3: Implement both functions in `src/lib/managed-block.mjs`**

Count how many times each marker appears. If both counts are 0, append: when the trimmed existing text is empty, write `B + '\n'`; otherwise write `existing.trimEnd() + '\n\n' + B + '\n'`. If both counts are 1 and the start comes before the end, replace the range from the start of the start marker through the end of the end marker. Any other case is an error. Compare the new text with the old and write only if it differs. A missing file (`ENOENT`) means `'created'`.

- [ ] **Step 4: Run the tests to verify they pass**

Run: `npm test`
Expected: all tests pass.
